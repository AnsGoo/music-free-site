# 音乐分享

相关文档：[MusicFreeServe 集成](/serve) · [歌单](/playlist) · [用户](/user)

## 1. 模块概述

**音乐分享**允许把本地曲库中的**歌曲或歌单**分享出去，供其他用户直接下载并自动入库；也可下载他人分享的音乐。该能力默认关闭，需在「用户配置」中显式开启，并与 [MusicFreeServe 集成](/serve) 配合完成节点引导。

## 2. 开启与前置条件

1. 在「用户配置」中完成 MusicFreeServe 的地址与 API Key 配置并启用；
2. 在「用户配置 → **音乐分享**」卡片中打开开关；
3. **Docker 部署必须使用 host 网络模式（`network_mode: host`）**，否则分享节点无法正常发现与连接；飞牛原生应用不受影响。

开启后，卡片会显示节点状态、链路状态与网络观测，并支持一键刷新。

## 3. 分享（发布方）

### 3.1 分享歌曲 / 歌单

- 在「音乐分享」卡片搜索本地歌曲，或多选后点击「分享所选歌曲」；
- 也可直接选择一张歌单进行分享；
- 分享记录持久化，进程重启或链路重连后自动恢复。

![](/img/platform-playlist.webp)

### 3.2 歌单分享与文件标识

在歌单详情的「共享」弹窗中勾选「分享歌曲」后：

- 歌单内歌曲会作为分享内容发布；
- 歌单同步到 serve 时，每条曲目会附带**文件标识（哈希）**，订阅方据此可直接下载；
- 关闭勾选或关闭共享会撤回该歌单的分享。

### 3.3 撤回

在分享列表中点击「撤回」会撤销发布并删除记录，**不会删除本地文件**。

## 4. 下载（接收方）

- 在「音乐分享」卡片的下载区输入**文件标识**（可附文件名）→「下载到音乐库」；
- 在**共享歌单详情**页，可对携带文件标识的曲目逐曲下载，或在标题栏「全部下载」批量加入队列；
- 下载固定落入默认音乐库 `music.library_path`，完成后自动触发扫描入库，并成为新的分享来源。

### 4.1 自动重试

- 下载失败的任务会**自动重新入队**，单首最多重试 **3 次**（不含首次）；
- 也可在界面**手动重试**（手动重试会重置自动重试预算）；
- 达到上限后保持 `failed`，可稍后重试。

## 5. 约束

| 约束       | 说明                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 音乐源     | 本地源直接分享；WebDAV 等远程源会先缓存到本地再发布                       |
| 音频格式   | mp3 / flac / wav / ogg / opus / m4a / aac / wma（按内容嗅探，与扩展名无关） |
| 单文件上限 | 200 MiB                                                                  |
| 不覆盖     | 目标同名且内容不同的文件会被拒绝覆盖                                       |
| 网络       | 部分网络环境（如对称 NAT / CGNAT）打洞可能失败，属预期情况                 |

## 6. 常见问题

**Q：开启后提示需要先配置 MusicFreeServe？**  
A：音乐分享依赖 serve 进行节点引导，请先在「用户配置」完成 MusicFreeServe 配置。

**Q：Docker 部署后分享不可用？**  
A：请改用 host 网络模式（`network_mode: host`）后重启，并确保出网能力正常。

**Q：下载很慢或失败？**  
A：可能是分享方离线或处于不支持打洞的网络环境，可稍后重试；下载任务会自动重试。

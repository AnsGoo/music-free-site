# 发布日志

本文档记录 MusicFree 各版本的变更摘要、升级注意事项与破坏性变更。功能细节请参阅 [功能特性](/feature) 与各功能模块文档。

---

## 阅读说明

### 版本号规则

- **稳定版**：`V1.x.y`（如 `V1.1.5`）
- **预发布版**：`v1.x.y-alpha.nn`（如 `v1.2.0-alpha.09`），功能可能仍在快速迭代，不建议直接用于生产环境

### 升级建议

1. 升级前备份 `data/music.db` 与配置文件
2. 关注各版本 **升级说明** 中的扫描、插件、配置变更
3. Alpha 版本之间可能包含数据库自动迁移；首次启动后观察日志是否正常
4. 插件（尤其 `mf-plugin-gomusicdl`）版本与宿主需匹配，升级后建议在管理端确认插件已更新

Docker 升级示例：

```bash
docker pull ansgoo/music-free:latest
docker compose up -d
```

## V1.2.6

> 发布日期：2026年11月8日

本次更新以「让 NAS 上听的歌，也回到你的曲库」为主题：完成与**飞牛音乐（fnOS「音乐」）**的深度联动，听歌记录、歌单、收藏三类数据可自动同步；同时重做了音频流的 HTTP Range 支持，转码歌曲拖动进度条不再卡顿或失效。

### 更新特性

#### 飞牛音乐（fnOS）深度联动

MusicFree 现在可以和飞牛 fnOS「音乐」应用双向配合：**从飞牛读数据（听歌记录、收藏），向飞牛写歌单**（基于 fnOS 音乐 1.0.10 实测接口实现）。

在「用户配置 → FnMusic 配置」中填写飞牛地址、用户名与密码，三项能力各自独立开关：

- **听歌记录**（`listen_record`）：把飞牛里的收听同步为本机播放记录
- **歌单同步**（`sync_playlist`）：把本机歌单镜像到飞牛音乐
- **收藏导入**（`sync_favorite`）：把飞牛里的收藏导入本机

> 飞牛地址只需填主机（如 `https://192.168.124.18:5667`），会自动补全 `/music/api/v1`；自签证书默认「先严格校验、失败后降级重试」。

##### 听歌记录同步

- **定时轮询**：固定每分钟检查一次飞牛最近播放列表，首轮只建立基线（**不导入历史**），之后把「新进入列表 / 序号前移」的曲目记为一次播放；`played_at` 取检查时刻，`client_id` 记为 `fnos-music`。
- **曲目匹配**：按「文件路径尾部（容忍挂载前缀差异）→ 标题 + 艺术家 → 标题 + 时长（±2 秒）」三级匹配；未匹配的曲目最多重试 12 轮。
- **即时推送**：本地写入成功后，若已启用 music-free-serve 的 `listen_record`，会立即异步推送，远程来源标记为 `fn-music`，与本地播放区分。
- **会话稳定**：使用由用户 ID 派生的固定 deviceId，重复登录只覆盖同一条会话；token 缓存 12 小时，过期自动重登。

> 受飞牛接口限制：同一检查间隔内的多次播放只记 1 次，同一首歌连续重复播放检测不到，也不导入飞牛的历史累计次数。

##### 歌单镜像同步

- **单向镜像**：以 MusicFree 为准。用户级开关打开后，还需在**歌单详情页**单独打开「同步到飞牛音乐」，该歌单才会被创建 / 更新；你在飞牛里自建的歌单永远不会被接管（重名时新建「名字（music-free）」）。
- **顺序保真**：飞牛侧无手动排序，镜像时按本地顺序重建，保证两边曲目顺序一致；大歌单会逐条写入，耗时较长。
- **封面同步**：本地歌单封面会一并上传并挂载到飞牛歌单；改名等操作不会清空已在 App 里设置的封面。
- **删除语义**：删除本地歌单会先删除飞牛镜像（失败则中止本地删除）；**关闭开关只停止同步，不删除飞牛上已有歌单**；远端歌单被手动删除后，下次同步会自动重建。
- **触发时机**：歌单变更即时同步 + 启动时与每 8 小时全量对账，也可在设置页或歌单页手动「立即同步」。

##### 收藏导入（单向）

- 把飞牛音乐 App 里的收藏曲目**单向导入**本机收藏，**绝不向飞牛写入任何数据**。
- 固定每分钟检查一次；通过集合指纹短路，无变化时不重复匹配；本地取消收藏不会影响飞牛，飞牛取消收藏也不会删除本地收藏。
- 幂等导入，重复执行不会产生重复收藏；未匹配的曲目只计数、不阻断其余导入。
- 受接口限制，收藏时间记为**导入时刻**（飞牛不返回收藏时间）。

##### 局域网自动发现

- 设置页新增「扫描局域网」：从**服务端所在网络**扫描飞牛默认端口 `5667/5666`，未发现音乐应用时回退 `443/80`（反向代理场景）。
- 扫描不携带任何账号密码；同一时间只允许一个扫描任务；结果可一键填入地址并自动检测连接。
- Docker 桥接网络或远端服务器部署时，请手动填写 NAS 地址。

#### 音频流：转码歌曲也能随意拖动进度条

- **转码流支持 HTTP Range**：转码输出（CBR mp3）现在会返回 `206 + Content-Range`，字节偏移按码率换算为时间偏移后用 `-ss` 续流；浏览器、AVPlayer、ExoPlayer 等可以正常拖动进度条，不再把转码流当作不可定位资源。
- **远端文件（WebDAV）支持 Range**：按源自身的区间读取能力取字节段，支持 `bytes=N-M` / `bytes=N-` / 后缀区间；起点越界返回 `416`，文件大小未知时如实宣告 `Accept-Ranges: none`。
- **不再重复转码**：请求末尾 1 个字节（客户端续流后的常见行为）不再退化为整首重新转码；已写满声明的 `Content-Length` 后主动结束 ffmpeg，不再产生 broken pipe 与错误状态码。
- **兼容旧路径**：原生 seek 不可用时，前端会自动回退到 `timeOffset` 重新拉流，并正确换算进度条与时长。

#### P2P 连通性诊断

「用户配置 → P2P 分享」新增「诊断」按钮，一次看清链路问题：

- **STUN 探测**：逐个 STUN 服务器报告是否可达、反射地址与耗时；全部失败时会提示 UDP/STUN 出网可能被阻断。
- **持有者直连探测**：输入可选的文件哈希（64 位十六进制）后，逐个尝试直连持有者，报告选中的候选类型或失败原因。
- **链路与时钟**：展示节点 ID、链路状态、注册中心地址、ICE 服务器，以及**本机与注册中心的时钟偏差**。
- **原因提示**：根据探测结果给出最可能的原因（时钟偏差超过 60 秒会丢弃信令、对称 NAT/CGNAT 需要 TURN 等）。

#### 艺术家列表默认排序与歌曲数

- 「艺术家」页默认按**当前用户的听歌历史播放次数降序**排列，其次按艺术家**创建时间降序**，最后用名称与 ID 兜底，保证分页稳定，不再重复或漏项。
- 只统计当前用户、且排除已删除歌曲；其他用户的播放不影响你的排序。
- 搜索时仍保持原有的相关性排序（前缀匹配优先）。
- OpenSubsonic `search2` / `search3` 的艺术家对象补充了 `songCount`（标准 schema 外的字段，部分客户端会展示歌曲数量）。

#### 播放页：队列内直接刮削元数据

- 播放页新增管理员「刮削元数据」按钮，无需离开播放页即可为当前歌曲重新刮削。
- 刮削完成后会即时刷新当前歌曲的元数据、封面与歌词，**并同步更新播放队列中已存在的该歌曲条目**，无需切歌重载。
- 歌词滚动改为在歌词容器内居中，不再带动整页滚动。

#### 播放统计口径统一

- 听歌统计现在**统一由 `/rest/stream` 取流驱动**（飞牛音乐同步写入的记录除外）：成功返回音频且为 GET 时记账；`scrobble` 接口仍保留以兼容客户端，但只记录日志、不再落库。
- **去重窗口**按歌曲时长计算（`clamp(歌曲时长, 30s, 30m)`），默认按客户端隔离，拖动进度条或重复探测不会重复计数。
- 记录通过异步 worker 池写入，不阻塞音频主流程；数据库条件插入保证并发与重启后也不会重复。

#### 元数据编辑与导入优化

- 封面裁剪升级到 **Cropper.js 2.x**（Web Components）：1:1 选区，支持移动、缩放与八向拖拽手柄，导出尺寸校验保持 3000px。
- 网易云歌单导入对话框的结果区只在确有结果时展示，避免空状态占位。
- 飞牛音乐设置页调整了输入框与提示文本布局，P2P 诊断界面调整了按钮与表格布局。

#### 其他优化

- 飞牛音乐、music-free-serve、P2P 三个集成改为通过窄接口解耦，减少相互影响，后续维护与排障更清晰。
- 前端依赖升级（Cropper.js 2.x、oxlint 等），构建与检查链路同步更新。

### 修复

- 修复 **play:Sub** 等通过 POST body 传递参数的 OpenSubsonic 客户端出现「歌曲数量异常 / 列表为空」的问题
- 修复切歌后新歌不自动播放的问题（加载完成后按播放状态补一次播放）
- 修复转码流拖动进度条后进度回退、无响应，以及 AVPlayer 判定「无法播放」的问题
- 修复播放页歌词自动滚动带动整页滚动的问题
- 修复网易云导入结果区与封面裁剪在部分场景下的显示 / 导出异常

### 升级说明

1. **镜像 / 应用版本**：直接替换为 `V1.2.6` 镜像或下载对应飞牛 FPK，配置会自动补全；默认端口仍为 `14533`，无需调整映射。
2. **新增 `play_history` 配置段**：`record_on_stream`（默认 `true`）、`dedup_by_client_id`（默认 `true`）、`stream_workers` / `stream_queue_size`。默认值即推荐值，不配置也可正常使用。
3. **新增 `fn_music` 配置段**：默认启用；`enabled: false` 可一次性关闭所有用户的飞牛定时任务；`tls_skip_verify: true` 适用于自签证书的局域网部署（会跳过证书校验）。
4. **飞牛音乐需要用户级开关**：在「用户配置 → FnMusic 配置」中填写并打开对应开关后才会访问飞牛；未配置时不会产生任何后台请求。
5. **听歌统计行为变化（注意）**：统计改为取流驱动，`scrobble` 不再写入播放记录；依赖 scrobble 上报的第三方流程请知悉，历史数据不受影响。
6. **P2P / 音乐分享**：Docker 部署仍需 **host 网络模式**；遇到连接不稳定时，可先用设置页的「诊断」确认 STUN、时钟偏差与持有者直连情况。

## V1.2.5

> 发布日期：2026年10月5日

本次更新以「打通生态、让歌流动起来」为主题：完成了与 `music-free-serve` 的深度集成（歌单同步、共享与远程发现），并新增音乐分享与下载能力。**注意：服务默认监听端口由 `4533` 调整为 `14533`。**

### 更新特性

#### 与 MusicFreeServe 集成：歌单同步、共享与订阅

MusicFree 现在可作为 [music-free-serve](https://github.com/AnsGoo/music-free-serve) 的客户端，把歌单「发出去、收进来」。所有能力需先在「用户配置」中填写 serve 的 `HOST_URL` / `API_KEY` 并勾选启用。

- **歌单同步**：开启后，用户的公开歌单会增量推送到 serve（创建 / 更新 / 删除），并有每 8 小时一次的全量对账兜底。
- **歌单共享**：歌单详情页可开启「共享」（`unlisted` / `public`），自动同步到 serve 并生成分享码；共享中的歌单为只读。
- **共享歌单 / 共享码订阅**：浏览公开共享歌单或输入共享码，一键订阅为本地只读副本。
- **发现歌单**：浏览 serve 发现库的平台 / 分类 / 歌单，支持关键词检索，订阅后导入本地并按标题 + 艺术家匹配曲库。
- **推荐页**：歌单页默认进入「推荐」页签，展示「热门歌单」与「推荐歌单」。

> 远程关闭共享后，本地订阅副本会在打开或同步时自动转为自有可编辑歌单，不会变成死链。

详见 [MusicFreeServe 集成](/serve)。

#### 音乐分享与下载

新增音乐分享能力：可把本地曲库中的歌曲、歌单分享出去，其他用户可直接下载并自动入库。功能默认关闭，需在「用户配置 → 音乐分享」中显式开启。

- **分享**：选择本地歌曲或整张歌单发布分享；分享记录持久化，重启后自动恢复。
- **附带文件标识**：开启歌单分享后，同步到 serve 的曲目会附带文件标识，订阅方可直接下载。
- **下载与重试**：按文件标识下载到默认音乐库并自动扫描入库；失败任务自动重试（单曲最多 3 次），也可手动重试。
- **状态可视**：分享卡片实时展示节点状态、链路与网络观测，支持一键刷新。

> 约束：本地源直接分享，WebDAV 等远程源会先缓存到本地再发布；单文件上限 200 MiB；支持 mp3 / flac / wav / ogg / opus / m4a / aac / wma（按内容嗅探）；部分网络环境（如对称 NAT / CGNAT）打洞可能失败。

详见 [音乐分享](/share)。

创建与编辑歌单时新增「描述」字段，可在详情页展示简介，方便整理与分享。

- 「用户设置」页重构为标签页布局，将音乐配置与分享设置分区管理。

#### 其他优化

- 全新 Logo 与应用图标。
- 封面图片自动压缩，降低存储占用、提升加载速度。
- 平台列表仅返回已启用的平台。
- 主题支持跟随系统模式。
- 新增分享 / 下载列表分页。

### 修复

- 修复了同步歌单提示文本换行异常
- 修复了订阅歌单相关组件属性绑定异常
- 修复了下载重试提示与测试连接状态显示的逻辑异常

### 升级说明

1. **默认端口变更（BREAKING）**：服务默认监听端口由 `4533` 调整为 `14533`。已有部署请在 `config.yaml` 中显式保留原端口，或同步更新端口映射 / 反向代理 / 客户端连接地址；Docker 镜像现默认 `EXPOSE 14533`。
2. **MusicFreeServe 集成**：需自行部署并启用 `music-free-serve` 才能使用歌单同步、共享与发现；未启用时相关页签静默为空。
3. **音乐分享**：默认关闭，按需开启；**Docker 部署必须使用 host 网络模式（`network_mode: host`），否则音乐分享功能不可用**（飞牛原生应用不受影响）。

## V1.2.4

> 发布日期：2026年8月30日

### 更新特性

#### 从音乐文件夹一键生成歌单

在「歌单」页面，管理员可以指定音乐源和文件夹路径，一键将该文件夹下的歌曲生成为一张歌单（快照式，仅包含该文件夹直属的音乐文件，不递归子文件夹），歌单名默认取文件夹名，也可以手动指定。

非常适合把按照歌手、专辑、语种等整理的目录结构快速固化成歌单，方便后续播放与分享。

![folder-playlist.webp](https://ansgoo.github.io/music-free-site/img/folder-playlist.webp)

---

#### 自动清理空专辑与空艺术家

媒体库扫描完成后，会自动清理没有任何有效歌曲的专辑和艺术家，并同步清理关联数据（专辑-艺术家关系、歌曲-艺术家关系、用户收藏、评分等），让你的媒体库保持干净整洁。

---

#### 专辑列表默认按创建时间倒序

专辑列表的默认排序由名称正序调整为按创建时间倒序，最新入库的专辑排在最前面，更容易发现新添加的音乐。

---

#### DLNA 转码播放优化

针对 TCL、海信等电视上 DLNA 渲染器（Vewd 栈）无法正确显示总时长、无法拖动进度条的问题，DLNA 转码改为先写入临时文件，再通过 `http.ServeContent` 提供流：

- 返回精确的 `Content-Length`，并支持 HTTP Range（206）分段请求；
- ffmpeg 写入完整的 Info/Xing 头，渲染器可以据此正确显示总时长并拖动进度；
- 优先使用 FLAC STREAMINFO 的精确音频时长，避免元数据时长与实际不符导致 Content-Length 偏高、渲染器反复重拉。

---

### 修复

- 修复了歌单页面音乐源类型显示格式异常

## V1.2.3

> 发布日期：2026年8月17日

### 更新特性

#### 对Music Assistant 进行了支持

#### 什么是Music Assistant

> Music Assistant 的核心优势在于打破了音乐生态的壁垒，赋予你对自己音乐库和播放设备的完全控制权。它像一个音乐界的“万能遥控器”或“音乐库管家”，让你能自由地将各种音乐源与各种播放设备组合起来
> 支持广泛协议：支持 AirPlay、Chromecast、DLNA、Snapcast、MQTT 等多种协议;兼容新老设备：无论是崭新的智能音箱，还是20年前的老式功放，甚至是 DIY 的树莓派播放器，都能成为 Music Assistant 的播放终端

![device.webp](https://ansgoo.github.io/music-free-site/img/music-assistant.webp)

#### 为什么选择Music Assistant

DLNA 是本项目原生支持的硬件设备，Airplay、Chromecast 等其他设备因为社区对其第三方库的实现有差别，导致本项目无法直接集成，但是通过Music Assistant可以集成任意硬件设备，可通过Music Free直接将单曲、专辑、歌单播放到Music Assistant 的Player。

在设备管理页面可以添加Music Assistant 的Player，并支持将其添加到设备列表中来，设备列表中的设备只有管理添加之后，并授权给某个普通用户，则普通用户可以正常使用该设备进行音乐播放

![device.webp](https://ansgoo.github.io/music-free-site/img/music-assistant-device.webp)

#### 如何使用

1. 部署`Music Assistant`,并获取`Music Assistant` 的访问授权`token`（一般Music Assistant 是docker Host 网络模式部署，web访问端口为8095）
2. 打开`Music Assistant` 设置，添加音乐源，选择  `OpenSubsonic Media Server Library`插件,并配置`Music Free` 的地址、用户名、密码(`MusicFree` 支持所有的Opensubsnoic协议，`Music Assistant`默认用自己音乐库进行播放，因此你播放到Music Assistant的音乐必须在他的库里有)，等待同步完即可
3. 打开`Music Free` 进入「系统配置」页面 配置`Music Assistant`的访问地址、账号、token，并选择启用`Music Assistant`
4. 在设备发现页即可看到`Music Assistant` 发现的局域网设备


![device.webp](https://ansgoo.github.io/music-free-site/img/music-assistant-option.webp)

---

#### DLNA 局域网设备连接异常

如果是Docker 部署的需要将网络模式改为host 才能发现局域网设备，否则无法发现局域网设备，飞牛原生应用不存在这个问题，同时需要在配置项中配置部署的地址，否则发现设备之后，播放音乐会拉不到音乐流

```yaml
services:
  music-free:
    image: ansgoo/music-free:V1.2.3
    container_name: music-free
    restart: unless-stopped
    network_mode: host
    volumes:
      - /vol1/docker/music-free:/app/data
      - /vol1/music:/app/music
```

## V1.1.9

### 更新特性

#### 音乐去重：三步向导

管理后台 **音乐管理 → 音乐去重** 改为清晰的三步流程，降低误操作风险：

1. **生成指纹** —— 为缺失指纹的曲目批量补算 Chromaprint（已有指纹自动跳过）
2. **重复检测** —— 按可配置阈值比对全库，输出重复组与相似度分数
3. **去重** —— 组内手动勾选假删除，或 **按规则批量清理**（同专辑内保留无损 &gt; 码率 &gt; 时长；跨专辑重复默认全部保留）

![音乐去重三步流程](https://cdn.jsdelivr.net/gh/ansgoo/music-free-site@main/docs/public/img/remove-repeat.webp)

#### 媒体源扫描与指纹：更快、更稳

- **扫描提速**：并发 worker、目录 hash 增量跳过未变更路径；WebDAV 支持部分读取与单次 OpenStream 解析，减少远程 I/O
- **指纹与扫描解耦**：入库扫描不再强绑指纹计算；支持定时补指纹任务与管理端异步全库回填
- **指纹引擎**：内嵌 `chromaprint.wasm` + ffmpeg/ffprobe，**不再依赖系统 `fpcalc`**；WASM 堆内存可配置上限，大文件 / WebDAV 特殊格式拉取与运行时错误恢复更稳健，大幅降低了docker镜像体积
- **指纹调度**：支持任务中断与互斥锁，避免多任务争抢资源

#### ARM Docker 多架构镜像

CI 构建并推送 **amd64 + arm64** 双架构镜像，标签与 `V1.1.8` 一致，ARM NAS / 单板机可直接使用官方镜像。

#### 飞牛 fnOS 原生应用（FPK）

新增 **飞牛应用中心** 可安装的原生 `.fpk` 包（非 Docker 模板），支持桌面快捷方式启停与向导配置音乐库路径；Release 流水线同时产出 **amd64 / arm64** 安装包

#### 其他改进

- **WebDAV 媒体源**：在开启「允许回写音乐源文件标签」时，清洗 / 刮削 / 元数据编辑可写回远程标签（需 WebDAV PUT 权限）
- **标签清洗**：内置 `RULE-03` 扩展支持标题前导下划线序号（如 `_01.`）清理
- **远程搜索 / 下载**：插件选项展示插件图标，远程曲目列表增加加载骨架屏
- **默认策略**：新装默认关闭「回写音频源文件标签」，降低误改 NAS 原文件风险（可在 **系统设置** 中开启）
